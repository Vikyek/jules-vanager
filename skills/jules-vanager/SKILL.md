# Google Jules Manager & Automation Suite (`jules-vanager`)

`jules-vanager` provides programmatic control, background monitoring, and lifecycle automation for Google Jules (`jules.googleapis.com/v1alpha`), Google's autonomous cloud coding agent.

## When to Activate

Activate this skill when:
- Offloading routine, repetitive, or long-running tasks (linting, unit test generation, docstring additions, dependency upgrades).
- Checking the status or progress of active Google Jules tasks.
- Responding to queries or confirmations asked by Jules on an active session.
- Reviewing, testing, and merging Pull Requests generated by Jules (`gh pr list --author app/jules`).
- Automating background listener passes to unstuck stalled sessions.

Do NOT activate for:
- Synchronous edits requiring immediate local terminal execution in the current turn.
- Simple 1-line changes easily done locally.

---

## Authentication & Requirements

`jules-vanager` requires:
1. **`JULES_API_KEY`**: An official Jules API token (prefix `AQ.`, ~53 chars) or an OAuth2 bearer token (`Bearer ya29.`).
   - Sourced from environment or `~/.gemini/config/.vault_credentials.env`.
   - *Note: Standard Gemini API keys (`AIza...`) will fail with 401.*
2. **GitHub CLI (`gh`)**: Authenticated with push/merge access to target repositories.

## Command Reference & Workflows

### 1. Fast Task Offloading (`jules-start`)

Launch a task on Google Jules with automatic directory and git remote resolution:

```bash
# Offload task on current git repository:
jules-start "Add comprehensive unit tests for auth middleware and verify test coverage"

# Offload on a specific repository by name or path:
jules-start paru-wrapper "Implement quiet flag for pacman output and update manpages"
jules-start ~/Projects/agv-dispatcher "Add health-check endpoint"

# With branch override, prompt file, or dry-run preview:
jules-start -p my-repo -f task_spec.md --branch develop --open
jules-start my-repo "Test prompt" --dry-run
```

### 2. Session & Source Management (`jules-vanager`)

Inspect registered sources and active sessions:

```bash
# List all registered repositories/sources
jules-vanager list-sources

# List active sessions and their current state
jules-vanager list-sessions

# Get detailed session info and activity trajectory
jules-vanager get-session --session-id "<session_id>"
```

### 3. Answering Queries from Jules

When a session enters `AWAITING_USER_FEEDBACK`:

```bash
jules-vanager send-message \
  --session-id "<session_id>" \
  --message "Use GPL-3.0-only for the license entry and export the new function in index.ts."
```

### 4. Background Listener & Auto-PR Handler (`jules-listener`)

Run a single lifecycle pass to detect stalled sessions, send nudge prompts, verify tests, and auto-merge clean PRs:

```bash
# Run one immediate audit pass
jules-listener --once

# Stream live status metrics (ANSI or plain text)
jules-hud --format text
```

## Pull Request Lifecycle & Verification

When Jules completes a task and opens a GitHub PR:
1. Query active Jules PRs:
   ```bash
   gh pr list --author app/jules
   ```
2. Checkout and run test suite:
   ```bash
   gh pr checkout <PR_NUMBER>
   # Run project test command (e.g. pytest, npm test, cargo test)
   ```
3. If clean and verified, merge and delete branch:
   ```bash
   gh pr merge <PR_NUMBER> --squash --delete-branch
   ```
4. Archive the completed session:
   ```bash
   jules-vanager archive-session --session-id "<session_id>"
   ```
