# 🤖 jules-vanager — Workspace Guidelines & Architecture Reference

## 📌 Codebase Purpose & Goals

`jules-vanager` is a standalone management suite for the Google Jules API (`jules.googleapis.com/v1alpha`), background listener daemon, interactive curses terminal interface (`jules-tui`), and real-time status bar HUD (`jules-hud`). 

The core goal is to automate routine maintenance, linting, syntax verification, PR reviews, and session auto-merging/archiving across local repositories (`~/Projects/*`), providing both automated background handling and an interactive terminal management interface.

## 🎨 Visual Identity & Color Tokens (`jules_tui.py` & `jules_hud.py`)

Visual hierarchy relies on Python `curses` color pairs and ANSI escape codes:

### Curses Color Pair Matrix (`jules_tui.py`)
- **Pair 1**: `COLOR_YELLOW` / Default BG — Main text, session prompts, and general UI labels.
- **Pair 2**: `COLOR_GREEN` / Default BG — Completed state badges (`SUCCEEDED`, `COMPLETED`, `MERGED`, `RESOLVED`).
- **Pair 3**: `COLOR_RED` / Default BG — Feedback warnings, active error indicators, and failure badges (`PR_CHECK_FAIL`).
- **Pair 4**: `COLOR_RED` / `COLOR_YELLOW` — Topbar normal header status.
- **Pair 5**: `COLOR_BLACK` / `COLOR_YELLOW` — Active list item selection highlight bar.
- **Pair 6**: `COLOR_BLACK` / `COLOR_RED` — Critical alert / Service stopped topbar header.
- **Pair 7**: `COLOR_CYAN` / Default BG — Activity details, prompt responses, and suggestions text.

### ANSI HUD Palette (`jules_hud.py`)
- **Mode Indicators**: `\033[1;32m` (CONTINUOUS / Green), `\033[1;33m` (ONCE / Yellow), `\033[1;31m` (OFFLINE / Red).
- **Queries Alert**: `\033[1;33m⚠️ Queries: N` (Yellow) vs `\033[0;32m✓ Queries: 0` (Green).
- **PR Counter**: `\033[1;36m📦 PRs: N` (Cyan).
- **Archived Counter**: `\033[0;35m📁 Archived: N` (Magenta).

## 📊 Native Data Shapes & Session State Hierarchy

### API & Synthetic Session Lifecycle States
1. `IN_PROGRESS` / `RUNNING`: Active processing state. Priority 0 in TUI list.
2. `AWAITING_INPUT`: Active task requiring user prompt reply. Priority 2 in TUI list.
3. `COMPLETED` / `SUCCEEDED` / `RESOLVED` / `MERGED`: Finished session with clean PR or task completion. Priority 1 in TUI list.
4. `ARCHIVED` / `CLOSED`: Inactive session archived on Google API or local storage.
5. `UNASSIGNED_PR`: Synthetic session generated by scanning local repositories (`~/Projects/*`) for open Jules PRs lacking API session IDs.
6. `PR_CONFLICT` / `PR_CHECK_FAIL` / `WORKFLOW_APPROVAL_REQ`: Special branch conditions needing intervention.

## 🛠️ CLI Subcommands (`jules-manager`)

- `jules-manager list-sources`: List registered codebase repositories on Google Jules API.
- `jules-manager list-sessions [--include-archived]`: Fetch session collection.
- `jules-manager create-session --prompt "<prompt>" --repo "<repo>" [--branch "<branch>"]`: Spawn new API task.
- `jules-manager get-activities --session-id <id>`: Fetch full message and code generation trajectory.
- `jules-manager send-message --session-id <id> --message "<text>"`: Respond to an active session query.
- `jules-manager archive-session --session-id <id>`: Mark session as archived.
- `jules-manager unarchive-session --session-id <id>`: Restore archived session.

## ⚠️ Development & Execution Invariants

1. **Non-Blocking UI Threading**: All API fetches (`list_sessions`, `get_activities`) and repository subprocess calls in `jules_tui.py` MUST be offloaded to `ThreadPoolExecutor` workers. Never block the main curses event loop (`stdscr.getch()`).
2. **Subprocess Timeouts**: `subprocess.run` calls MUST specify a strict timeout (`timeout=2` or `timeout=5`) to avoid hangs on locked git indexes.
3. **Secret Isolation**: Configuration files holding API keys (`~/.gemini/config/.vault_credentials.env`) MUST use `chmod 600`.
